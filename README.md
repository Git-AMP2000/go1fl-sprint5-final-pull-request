# Модуль фитнес-трекера

Итоговое задание модуля 1 «Основы Go» (Яндекс Практикум): фитнес-трекер, разнесённый по пяти внутренним пакетам. Приложение рассчитывает дистанцию, среднюю скорость и расход энергии для бега, ходьбы и дневной активности, а затем выводит отчёты по записям.

- Шаблон задания: <https://github.com/Yandex-Practicum/go1fl-sprint5-final>
- Модуль Go: `github.com/Yandex-Practicum/tracker`
- Минимальная версия Go: **1.24.1** (см. `go.mod`)
- Внешние зависимости приложения: отсутствуют, используется только стандартная библиотека. `testify` применяется в тестах.

## Быстрый запуск

Из корня проекта:

```bash
go mod download
go run ./cmd/tracker
```

Проверка кода:

```bash
gofmt -l .
go vet ./...
go test -v ./...
```

`cmd/tracker/main.go` содержит демонстрационный набор данных, включая намеренно ошибочные строки. Корректные записи выводятся в stdout, ошибки разбираются и логируются в stderr через стандартный пакет `log`; обработка остальных записей при этом продолжается.

## Соответствие техническому заданию

| Пакет | Реализовано |
|---|---|
| `spentenergy` | Экспортируемые `Distance`, `MeanSpeed`, `RunningSpentCalories`, `WalkingSpentCalories`; исходные константы расчётов сохранены. |
| `personaldata` | Структура `Personal{Name string, Weight float64, Height float64}` и метод `Print()` с форматом `Имя / Вес / Рост`. |
| `trainings` | Структура `Training` со встроенной `personaldata.Personal`; указательный метод `Parse` и метод `ActionInfo` для типов `Ходьба` и `Бег`. |
| `daysteps` | Структура `DaySteps` со встроенной `personaldata.Personal`; указательный метод `Parse` и метод `ActionInfo` для прогулки. |
| `actioninfo` | Интерфейс `DataParser` с методами `Parse(string) error` и `ActionInfo() (string, error)`; функция `Info([]string, DataParser)`. |

Методы `Parse` имеют получателя-указатель, чтобы записывать результат в структуру. Методы `ActionInfo` и `Print` используют получателя-значение. Встроенная структура `Personal` даёт обеим прикладным структурам прямой доступ к полям `Name`, `Weight`, `Height` и методу `Print`.

## Форматы входных данных

Дневная активность:

```text
678,0h50m
```

Тренировка:

```text
3456,Ходьба,3h00m
678,Бег,0h5m
```

Правила разбора:

- количество полей строго проверяется: 2 для прогулки, 3 для тренировки;
- шаги преобразуются через `strconv.Atoi` и должны быть положительными;
- продолжительность преобразуется через `time.ParseDuration` и должна быть положительной;
- пробелы вокруг полей намеренно не удаляются, чтобы не принимать искажённый формат;
- поля структуры обновляются только после успешного разбора всей строки;
- тип тренировки сохраняется при разборе, а неизвестный тип приводит к ошибке в `ActionInfo` с текстом `неизвестный тип тренировки`.

## Формулы расчёта

Единицы измерения: рост — метры, вес — килограммы, дистанция — километры, скорость — км/ч, энергия — ккал.

```text
длина шага = height * 0.45
дистанция  = steps * длина шага / 1000
скорость   = дистанция / duration.Hours()

калории бега   = weight * скорость * duration.Minutes() / 60
калории ходьбы = калории бега * 0.5
```

В расчётах калорий используется неокруглённая средняя скорость. Округление до двух знаков выполняется только при формировании итоговой строки. Для некорректных параметров функции калорий возвращают `0` и ошибку; проверяются положительные шаги, вес, рост и продолжительность, а также конечность чисел и результата.

## Обработка ошибок

- `Parse` возвращает ошибку с контекстом неверного поля.
- `ActionInfo` при ошибке возвращает пустую строку и ошибку.
- `Info` логирует ошибку разбора или формирования отчёта и переходит к следующей записи.
- Отрицательные шаги и неположительная продолжительность не приводят к некорректному расчёту скорости: `MeanSpeed` возвращает `0`.
